Tema 5 · Levantamento e requisitos

Requisitos de sistemas de informação

Requisitos funcionais e não funcionais

Um requisito descreve o que o sistema deve fazer ou as qualidades que deve ter. É o contrato entre o cliente e a equipa de desenvolvimento: sem requisitos claros, cada parte imagina um sistema diferente.

Requisitos funcionais e não funcionais

Requisitos funcionais (RF)Requisitos não funcionais (RNF)
O que descrevemAs funções e os serviços que o sistema oferece.As qualidades e restrições com que essas funções são prestadas.
Pergunta«O que faz o sistema?»«Com que qualidade?»
Exemplo«O sistema deve permitir registar um empréstimo.»«O registo de um empréstimo deve demorar menos de 3 segundos.»

Os requisitos não funcionais abrangem, por exemplo, desempenho, segurança, usabilidade, disponibilidade, compatibilidade e legislação aplicável (como a proteção de dados pessoais).

Características de um bom requisito

  • Claro e não ambíguo — só pode ser entendido de uma forma.
  • Único — descreve uma só coisa.
  • Verificável — é possível testar se foi cumprido (evitar «rápido», «fácil»).
  • Identificado — tem um código (RF01, RNF03) para ser rastreado nos modelos.
  • Prioritário — é essencial, desejável ou opcional.

Escreva os requisitos funcionais na forma «O sistema deve + verbo + o quê». Por exemplo: «O sistema deve permitir pesquisar livros por título».

Atividade

Elaborar uma lista de requisitos para um sistema de gestão de biblioteca

Com base nas necessidades levantadas na entrevista, elabore a lista de requisitos de um sistema de gestão de biblioteca.

  1. Escreva pelo menos 10 requisitos funcionais, com código.
  2. Escreva pelo menos 5 requisitos não funcionais, verificáveis.
  3. Atribua uma prioridade (essencial, desejável ou opcional) a cada um.

Em resumo

  • Os requisitos funcionais dizem o que o sistema faz; os não funcionais, com que qualidade.
  • Um bom requisito é claro, único, verificável e identificado.
  • Os requisitos são a base de todos os modelos que se constroem a seguir.
