Tema 8 · Modelação de dados

Introdução à modelação de dados

Entidades, atributos e relacionamentos

Todo o sistema de informação guarda dados. Antes de criar tabelas, é preciso decidir que dados são relevantes e como se relacionam. A modelação de dados responde a esta questão através de modelos que se vão tornando mais próximos da implementação.

NívelO que descreveExemplo
ConceptualOs dados do negócio, independentemente da tecnologia.Modelo Entidade-Relacionamento (ER)
LógicoOs dados organizados segundo um modelo de bases de dados.Modelo relacional (tabelas)
FísicoA implementação concreta num sistema de gestão de bases de dados.Tipos de dados, chaves, restrições

Os três elementos básicos

  • Entidade — algo do mundo real sobre o qual queremos guardar dados (Leitor, Livro, Aluno, Produto). Representa-se por um retângulo.
  • Atributo — uma característica da entidade (nome, ISBN, preço). Representa-se por uma elipse; o atributo que identifica cada ocorrência é sublinhado.
  • Relacionamento — a associação entre entidades (um Aluno frequenta uma Disciplina). Representa-se por um losango, com a cardinalidade nas ligações.

Uma ocorrência é um exemplar concreto da entidade: «Ana Reis» é uma ocorrência de Leitor. Quando o modelo ficar maior, representaremos os atributos listados dentro da própria entidade, para poupar espaço — é uma notação equivalente.

Em resumo

  • A modelação de dados passa por três níveis: conceptual, lógico e físico.
  • Uma entidade tem atributos; um deles identifica cada ocorrência.
  • Os relacionamentos associam entidades e levam cardinalidade.
  • O modelo Entidade-Relacionamento é o primeiro modelo de dados do projeto.

Parte 1 — Aprender passo a passo

Passo 1 — Porque precisamos de modelar os dados?

Imagina que uma escola quer criar um programa para guardar os nomes dos alunos, os emails e as turmas. Antes de criar a base de dados, é necessário decidir que informação guardar e como a organizar. A este planeamento chamamos modelação de dados.

Pergunta para pensar: Como conseguimos saber a que turma pertence cada aluno sem misturar toda a informação?

Passo 2 — Entidades

Uma entidade é algo sobre o qual queremos guardar informação: uma pessoa, um objeto ou um conceito.

Exemplos numa escola: ALUNO, PROFESSOR, TURMA e DISCIPLINA.
Exemplo numa biblioteca: LIVRO e AUTOR.

Passo 3 — Atributos

Os atributos são as características que descrevem uma entidade. Para a entidade ALUNO, podemos guardar o número, o nome e o email.

EntidadeAtributos
ALUNOnumero_aluno, nome, email, id_turma
TURMAid_turma, designacao
Não confundir: ALUNO é uma entidade; nome é um atributo.

Passo 4 — Tabelas, registos, campos e valores

Numa base de dados relacional, os dados são frequentemente organizados em tabelas.

numero_alunonomeemail
101Ana Silvaana@escola.pt
102João Costajoao@escola.pt
103Sara Lopessara@escola.pt
  • Tabela: conjunto organizado de dados.
  • Atributo/campo: coluna, por exemplo, nome.
  • Registo/tuplo: linha que contém os dados de uma ocorrência, por exemplo, os dados da Ana Silva.
  • Valor: dado específico numa célula, por exemplo, “Ana Silva”.

Passo 5 — Relacionamentos

Um relacionamento descreve a ligação entre entidades. Por exemplo, um aluno pertence a uma turma.

ALUNO
numero_aluno, nome, id_turma
— pertence a →
TURMA
id_turma, designacao

Neste exemplo simplificado, uma turma pode ter vários alunos e cada aluno pertence a uma turma. Esta relação é chamada um-para-muitos (1:N).

Passo 6 — Chave primária (PK) e chave estrangeira (FK)

Tabela TURMAdesignacao
id_turma (PK)10.º A
210.º B
numero_aluno (PK)nomeid_turma (FK)
101Ana Silva1
102João Costa1
103Sara Lopes2
  • PK — Chave primária: identifica de forma única cada registo da tabela.
  • FK — Chave estrangeira: campo que referencia uma chave de outra tabela e permite estabelecer a ligação.
O id_turma é PK na tabela TURMA e FK na tabela ALUNO. Assim, o valor 1 indica que Ana Silva pertence à turma 10.º A.

Passo 7 — Resumo para memorizar

  • Entidade: sobre o que guardamos informação.
  • Atributo: característica da entidade.
  • Registo/tuplo: linha da tabela.
  • Valor: conteúdo de uma célula.
  • Relacionamento: ligação entre entidades.
  • PK: identifica unicamente um registo.
  • FK: liga tabelas através de uma referência.
